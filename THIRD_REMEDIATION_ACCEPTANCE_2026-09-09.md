## Вердикт

контролируемой установки и live-проверки после явного разрешения пользователя.

- временный ключ создаётся через `os.CreateTemp`, синхронизируется и закрывается;
- невозможность сохранить corrupt key теперь прерывает замену;
- незавершённые записи manifest сохраняются;
- force-флаги из deploy-команды удалены;
- walkthrough отделяет завершённую кодовую проверку от ещё не выполненного deployment;
- количество тестов исправлено: 30 test functions / 33 RUN scenarios.

## Остаточный hardening, не блокирующий установку

`Lstat(dir)` с последующим `os.Chmod(dir)` и `os.CreateTemp(dir, ...)` не является полной
защитой от замены самого каталога между системными вызовами. Абсолютная защита требует
работы через открытый directory descriptor и `openat`/`renameat`.

В текущей модели каталог имеет режим `0700` и управляется root, поэтому такая атака
требует уже существующего root-доступа либо возможности изменять родительский каталог.
Это можно оставить отдельной hardening-задачей. Для аккуратности рекомендуется:

- удалить лишний path-based `os.Chmod(tmpPath, 0600)`, поскольку `os.CreateTemp` уже
  создаёт файл с режимом 0600;
- заменить `os.Chmod(dir, 0700)` на chmod через открытый проверенный descriptor;
- в будущем объединить directory validation и файловые операции через Linux `openat`.

## Разрешённый следующий этап

После подтверждения пользователя:

1. сделать резервную копию текущих настроек и точного `csrf.key`;
2. установить IPK обычной командой без force-флагов;
3. проверить запуск AWG Manager и все необходимые listeners;
4. войти заново в UI и выполнить полный browser smoke-test;
5. ротировать Telegram secret и немедленно отозвать legacy secret;
6. убедиться, что старая ссылка больше не подключается;
7. проверить Wireguard2, telemt, tproxy-server, Mihomo и пользовательский трафик;
8. дописать в walkthrough фактические результаты deployment, не выводя секреты.

До получения разрешения никаких операций на роутере выполнять не следует.
