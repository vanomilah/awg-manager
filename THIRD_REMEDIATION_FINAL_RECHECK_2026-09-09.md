# Финальная перепроверка `implementation_plan.md` и `walkthrough.md`

Дата: 2026-09-09

## Вердикт

Третья ремедиация в основном реализована: исправлен `preinst`, добавлено безопасное
Linux-открытие через `O_NOFOLLOW`, улучшена атомарная замена ключей, добавлены API-тесты и
собран IPK 2.17.36. Однако до развёртывания остаются два блокирующих security-дефекта в
key-file helper и несколько неточностей отчёта.

## Блокирующие замечания

### P1 — TOCTOU снова появляется при `os.Chmod(keyPath, 0600)`

`loadOrCreateKeyFile` безопасно открывает существующий файл через `openFileNoFollow`,
проверяет descriptor и читает его. Но затем descriptor закрывается, после чего вызывается
`os.Chmod(keyPath, 0600)` по имени пути. Между `Close` и `Chmod` путь может быть заменён на
symlink. Процесс AWG Manager работает от root, поэтому он способен изменить права
произвольного файла, на который указывает подменённая ссылка.

Исправление:

- выполнять `f.Chmod(0600)` на уже безопасно открытом descriptor до чтения/закрытия;
- удалить последующий `os.Chmod(keyPath, ...)` по имени;
- добавить Linux-тест, моделирующий замену path после открытия либо хотя бы проверяющий,
  что helper не вызывает path-based chmod для существующего файла.

### P1 — родительский каталог key files может быть symlink

Проверяется только конечный key path. `os.MkdirAll(dir, 0700)` допускает уже существующий
каталог-симлинк, а `os.Chmod(dir, 0700)` следует по нему. В результате ключи могут читаться
или создаваться за пределами ожидаемого каталога.

Исправление:

- проверить `dir` через `Lstat` и отклонить symlink/non-directory;
- для строгой защиты открыть доверенный parent directory и выполнять операции через
  `openat`/`renameat` с `O_DIRECTORY|O_NOFOLLOW`;
- минимум добавить тест `tproxy` directory is symlink и ожидать отказ без изменения
  целевой директории.

## Остальные замечания к реализации

### P1 — ошибка backup повреждённого ключа игнорируется

Если `os.Rename(keyPath, corruptPath)` завершается ошибкой, код просто оставляет
`backedUp=false`, а затем всё равно выполняет `os.Rename(tmpPath, keyPath)`. На Linux это
может заменить существующий corrupt key без сохранения backup. Ошибка backup должна
прерывать операцию; новый temp key следует удалить, исходный файл оставить без изменений.

### P2 — количество tgwebproxy-тестов в walkthrough указано неверно

В приведённом блоке находится 27 строк `=== RUN`, а заголовок и итог говорят о 23 тестах.
Не считать вручную: сохранять фактическую строку `ok` и получать число из полного вывода
скриптом, либо вообще не заявлять фиксированное количество.

### P2 — утверждение о полной верификации преждевременно

Walkthrough одновременно говорит «полностью верифицировано» и содержит только план
развёртывания, ожидающий подтверждения. Корректная формулировка: код и пакет проверены,
live deployment 2.17.36, ротация, logout и отрицательный тест старой ссылки ещё не
выполнены.

### P2 — `implementation_plan.md` отстаёт от фактического состояния

План всё ещё описывает действия как proposed changes и сохраняет маску со старыми
реальными prefix/suffix. После ротации использовать нейтральное `<redacted>`. План можно
оставить историческим, но нужно отметить выполненные пункты и незавершённый deployment.

## Минимум перед установкой

1. Перенести chmod существующего ключа на descriptor (`f.Chmod`).
2. Запретить symlink родительского key directory.
3. Прерывать замену при ошибке создания backup corrupt key.
4. Добавить три отрицательных теста для этих случаев.
5. Повторить core/API tests и пересобрать IPK 2.17.36.
6. Исправить формулировки и количество тестов в walkthrough.
7. Только после разрешения пользователя выполнить обычный `opkg install`, ротацию,
   re-login, браузерный smoke-test и отрицательную проверку старой ссылки.

До выполнения пунктов 1–5 текущий IPK не следует устанавливать как финальную сборку.
