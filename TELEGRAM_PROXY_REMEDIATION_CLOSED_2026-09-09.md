# Закрытие ремедиации Telegram Proxy 2.17.36

Дата: 2026-09-09

## Итог

Ремедиация принята и закрыта. Walkthrough согласуется с фактическими артефактами:

- пакет 2.17.36 установлен штатным `opkg install` без force-флагов;
- необходимые listeners и Wireguard2 после обновления работают;
- исторический и промежуточный Telegram secrets отозваны и проверены отрицательно;
- после финальной ротации `/reveal` не вызывался;
- текущий secret не попал в отчёт или QR-снимки;
- credential-снимки `v21736_tg_proxy_webproxy_modal.png` и
  `v21736_tg_proxy_direct_modal.png` действительно отсутствуют;
- актуальный `v21736_tg_proxy_card.png` показывает только нейтральное `(redacted)`;
- `POST /logout` корректно описан как завершение текущей сессии;
- `go test ./internal/tgwebproxy/...` повторно проходит;
- `git diff --check` не обнаруживает ошибок, кроме информационных предупреждений CRLF/LF.

Старый `tg_proxy_card_verified.png` содержит только частичную маску уже отозванного ключа
и не содержит QR-кода или полной ссылки. Его можно удалить для гигиены артефактов, но он
не компрометирует действующий secret.

## Остаточные задачи

Блокирующих задач нет. В будущий hardening backlog можно добавить directory operations
через `openat`/`renameat` и открытый `O_DIRECTORY|O_NOFOLLOW` descriptor. При текущем
root-owned каталоге с режимом 0700 это не блокирует эксплуатацию.

Финальный walkthrough может использоваться как отчёт о завершении работ.
