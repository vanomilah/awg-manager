## Неблокирующие, но важные уточнения

### 1. Обязателен реальный браузерный smoke-test `/csrf`

Браузер обычно не обязан посылать `Origin` на обычный same-origin GET. `Referer` также
может отсутствовать из-за Referrer-Policy или особенностей встроенного браузера. Поэтому
после требования Origin/Referer недостаточно проверить endpoint через Python.

Нужно открыть UI в используемом браузере и проверить все действия Telegram Web Proxy:

- загрузка карточки;
- открытие окна подключения;
- reveal;
- update/start/stop/rotate/revoke;
- отсутствие 403 в Network/Console.

Если UI не присылает оба заголовка, следует вернуть permissive GET `/csrf`, оставив
строгую проверку mutating endpoints. Cross-origin чтение ответа должен запрещать SOP/CORS,
а cookie должна иметь корректный SameSite. Не следует искусственно добавлять клиентский
`Origin`: браузер не разрешает JavaScript устанавливать этот заголовок вручную.

### 2. Ротацию `csrf.key` выполнять через rename, не безвозвратное удаление

После остановки daemon проверить точный путь через `lstat`, переименовать обычный файл в
резервную копию с timestamp, запустить daemon и проверить новый regular file размером 32
байта с режимом 0600. Удалять backup можно только после успешной проверки.

### 3. Отдельно подтвердить фактическое завершение административных сессий

Ротация CSRF key аннулирует ранее выданные CSRF-токены, но сама по себе не обязательно
удаляет сессии. Если SessionStore находится только в памяти и перезапуск действительно
очищает его, это нужно подтвердить тестом: старый cookie после рестарта получает 401.
Иначе потребуется явная очистка SessionStore либо ротация session key.

### 4. Leak check должен охватывать untracked и внешние артефакты

`git grep` проверяет только tracked-файлы и неизбежно найдёт допустимые имена полей вроде
`csrf_token`. Дополнительно проверить конкретные walkthrough/test artifacts и untracked
файлы, но не выводить найденные значения в консоль или новый отчёт. Старую маску с
реальными prefix/suffix лучше заменить нейтральным `<redacted>`, поскольку после ротации
она больше не нужна даже как пример.

### 5. Router operations должны иметь явную точку остановки

Агент может самостоятельно выполнить изменения кода, тесты и сборку. Перед остановкой
сервиса, ротацией секретов и установкой IPK он должен показать результаты локальной
проверки и запросить подтверждение. Следует предупредить о краткой недоступности порта
2222 во время рестарта.

## Решение

План можно запускать для этапов изменения кода, тестирования и подготовки IPK. Перед
live deployment требуется остановка для подтверждения. Браузерный smoke-test CSRF следует
считать обязательным условием принятия, а не факультативной проверкой.
